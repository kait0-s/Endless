# 部屋システム C++ 移行メモ（UE 5.6）

Blueprint の入口インターフェースを残しつつ、部屋の先読み、接続、保持数、ドア制御、候補地点からの小物生成を Native 実装へ移行した。

## 基本設定

- 操作距離: `150 cm`（XY 平面距離）
- 操作方向: ドア方向との内積 `0.5` 以上（正面から左右 60 度以内）
- 先読み距離: `600 cm`
- 先読み垂直許容: `250 cm`（上下階の誤先読み防止）
- 通過判定垂直許容: `200 cm`
- ドア開角度: `90 度`
- ドア開閉時間: `0.5 秒`
- 保持部屋: `Previous / Current / Next` の最大 3 部屋
- 部屋候補: Room 01〜14

## 接続規約

- `Lvl_StartCorridor` のユーザー調整済み出口をワールド原点 `(0, 0, 0)`、Yaw `0` の基準ソケットとする。
- 各 Room の Entry はローカル `(0, 0, 0)`、Yaw `0`。旧 `EntryAlignmentOverride (0, 50, 0)` は使用しない。
- `RoomSpawnPoint` はドア Actor 原点に一致し、相対 Transform は Identity とする。
- 壁厚は `20 cm`。接続面では手前側と次室側が各 `10 cm` を所有し、重なりも隙間も作らない。
- 開口は幅 `100 cm`、高さ `220 cm`。ドアスラブも同寸法とする。
- Manager は `EntryLocal.Inverse() * DesiredConnectionTransform` で Level Instance を整列する。
- Exit は各室で一意な `Exit_A`〜`Exit_C` を持ち、接続 Transform と閉鎖壁タグを個別管理する。
- 床上面は `Z=0`、天井高は `4.5 m`。複合形状は重ならない長方形床片の和集合として定義する。

## ドア所有権とストリーミング

- 接続部の実ドアは手前部屋で選択された Exit 1 枚だけを表示・衝突・操作対象にする。
- 次室の Entry Actor は管理用ソケットとして残し、Actor 全体の表示と衝突を抑止する。Actor 自体は削除しない。
- 古い Previous を破棄した時点で、保持される新しい Previous の Entry を再表示して閉じた境界に戻す。これにより最大 3 部屋を保ちながら背面に穴を作らない。
- 読み込み中は Exit を開かず、Level Instance の可視化と Entry/Exit 検出が完了した後に操作を再実行する。
- 入室時に有効 Exit 数と候補を確定する。01/02 と 04〜10 は 1〜3、03 は 1〜2 の範囲で抽選する。
- 先読みはプレイヤーに最も近い有効 Exit の1件だけとし、別 Exit へ移動した場合は未訪問の Next を解放して切り替える。
- Exit を開いた時点でその分岐を確定し、同じ部屋の他 Exit は閉鎖する。戻った場合は分岐選択を復元する。
- 無効 Exit はドアを非表示・非衝突・操作不可にし、対応する閉鎖壁を表示・衝突有効にする。
- 候補室はタグ `EndlessRoomOccupancy` の床・壁・階段・踊り場・手すりを3Dボックス群として計算し、Current/Previous との内部重なりを拒否する。候補を使い切った Exit は閉鎖し、未生成空間へ開かない。

## Room レイアウト

### 共通

- Entry はローカル原点、幅 `100 cm`・高さ `220 cm` の開口とする。
- Exit ごとに同寸法の開口、ドア、閉鎖壁を同じ Transform に配置する。
- 01/02 と 04〜10 は家具候補 4＋小物候補 2、03 は家具候補 2＋小物候補 2 を配置する。
- 候補地点は全ドアから `250 cm` 以上、床外周から `150 cm` 以上離し、Entryから各Exitへの主動線を避ける。

### 照明と2階層

- StartCorridorと全14室に、各Level所有のMovable Point Lightを配置する。Level Instanceの解放時に同時解放される。
- 1階層室は床片ごとに1灯、2階層室は各階2灯＋階段1灯の計5灯を基本とする。
- 主灯だけ影を有効にし、補助灯は影を無効にして重複シャドウを抑える。
- 階高は`450 cm`。階段は蹴上げ`25 cm`、踏面`50 cm`、幅`400 cm`とし、衝突付き段、両端踊り場、側面手すりを同一Levelに含める。
- 家具・小物候補は両階へ配置し、階段穴から180cm、同階のドアから250cm以上離す。

## Native 実装

- `BP_RoomDoor` の親は `AEndlessRoomDoor`、`Native Door Logic Enabled=true`。
- `BPI_Interactable.Interact` は `ProcessEvent` から `NativeInteract` へ渡し、Native 有効時に旧グラフを二重実行しない。
- ドア抑止は Mesh だけでなく Actor 全体の可視性・衝突へ適用し、フレーム等の競合も防ぐ。
- 操作判定は高さ差の影響を受けない XY 距離と、プレイヤー正面方向を使用する。
- `AEndlessRoomPropPoint` は BeginPlay で候補 Mesh を選び、ストリーミング Level の破棄と一緒に自動解放される。
- `FEndlessExitCandidate` は Exit ID、正確な Door/閉鎖壁、候補配列、接続 Transform を Level Instance 単位で保持する。
- 非表示先読み中はコンポーネントのキャッシュ境界を使わず、`CalcBounds` でタグ付きメッシュの3D占有範囲を取得する。
- 操作はドア中央高さ`110 cm`への3D距離で判定する。先読みと通過は垂直許容値も検査し、別階のドアを反応させない。

## 手動 PIE 確認

1. `Lvl_StartCorridor` から開始し、出口へ 600 cm 以内で先読みが完了すること。
2. 150 cm 以内で正面を向いて操作し、ロード完了後だけ開くこと。
3. 8部屋以上進み、正方形・長方形・L字・T字・段違い・2階層形の床、壁、ドアに意図しない段差や埋没がないこと。
4. 接続部にドア、衝突、操作対象が二重に存在しないこと。
5. 複数の有効Exit間で先読みが切り替わり、選んだExitだけが開くこと。無効Exitは壁として通れないこと。
6. 直前の部屋へ戻り、別Exitを選び直せること。さらに進んでも実体化する部屋が最大3室であること。
7. 家具・小物がドア開閉域と主動線を塞がないこと。
8. 上階・地下への階段を実際に歩行でき、踊り場と手すりが落下防止として機能すること。
9. 下階から上階ドア、上階から下階ドアへ操作・先読み・通過判定が発生しないこと。
10. 各階、階段、出入口、家具が過不足なく照らされ、補助灯による影の重なりが目立たないこと。
